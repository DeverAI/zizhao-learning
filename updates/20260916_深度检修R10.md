## 硬伤（必修，已修）

### H1 · `9**9**9` 能把进程打死（DoS）
- 现象：验证脚本执行 `calculator('9**9**9')` 后进程超时被杀。
- 原因：`agent_tools` 的 AST 计算器对幂运算无指数/底数限制。
- 修：新增 `MAX_POW_EXPONENT=64`、`MAX_POW_BASE=1e4`、`MAX_ABS_VALUE=1e15` 与 `_guard()`，
  `ast.Pow` 先校验操作数，中间结果统一过界检查（含 NaN / inf / 复数拦截）。
- 文件：`backend/services/agent_tools.py`

### H2 · 对话接口可跨用户读素材（越权泄漏）
- 实测：`db.get_material('matA')` 能直接拿到 `user_id='userA'` 的正文，`agent_chat` 无任何归属校验。
- 修：`agent_chat` 开头做归属校验，owner 为空或等于当前 uid 才采用，否则回退 `get_or_create_today`。
- 文件：`backend/services/agent_chat.py`

### H3 · `material_domains` 白名单形同虚设
- 实测：配置声明 4 个域，连续 pick 却返回 `gap_fill` / `upload` —— 白名单没进 SQL；
  而且实际产出的 `gap_fill` / `upload` / `knowledge` 三个域根本不在 `DOMAIN_ORDER` 里。
- 修：`pick_next_plan(domains=...)` 下推到 SQL `domain IN (...)`；
  `material_service` 两处调用传入 `settings["material_domains"]`；
  补全 `DEFAULT_SETTINGS.material_domains` 与 `DOMAIN_ORDER` 到 7 个域；
  顺带把轮转从"避开最近 1 个域"改成"避开最近 2 个域"（`skip_n` 自适应），做真正的三方向轮转。
- 文件：`backend/config.py`、`backend/models/database.py`、`backend/services/material_service.py`

### H4 · 审核门控不看配置里的字数门槛
- 实测：`body=600 字` 时 `rule_review` 只报"超长句"、`ok=True`，完全无视 `material_body_min_chars=1500`。
- 修：`rule_review` 从 settings 读 min/max，过短提示带"朗读不足，音频撑不满 Ns"；
  `generator` 与 `_rewrite_body` 的写死字数改为动态取 `generator.body_char_budget()`。
- 文件：`backend/services/review_service.py`、`backend/services/generator.py`

### H5 · Err.log 存错机制完全不存在（违反 AGENT.txt 硬规范）
- 实测：`logger.py` 是死代码（无模块引用），根目录无 `Err.log`。
- 修：重写 `logger.py`，新增 `record_error` / `read_errlog` / `clear_errlog`（线程安全追加写，清空内容不删文件）；
  `main.py` 接全局异常处理器 + 夜间巡检错误落盘。
- 文件：`backend/logger.py`、`backend/main.py`

### H6 · **`app.js` 解析期语法错误 → 前端整站白屏**（本轮最重）
- 现象：`node --check app.js` 报 `await is only valid in async functions`（第 231 行）。
- 原因：`renderHome()` 是同步函数，却在函数体里直接 `await api("/api/settings/apis")`。
  这是**解析期**错误，浏览器整个 script 不执行 → 登录页都渲染不出来，前端等于零。
- 附带：该处局部变量名叫 `view`，与全局 `const view = $("#view")` 同名遮蔽，是定时炸弹。
- 修：异步取配置包进 IIFE（`renderHome` 保持同步以便 `render()` 直接调用），变量改名为 `cfg`。
- 文件：`backend/static/app.js`

### H7 · **素材生成静默降级成占位模板**（核心功能一直是废的）
- 现象：GLM 全链路实测，`/api/material/refresh` 返回 `degraded=True`、
  `provider=fallback_template`、正文仅 316 字 → 审核 4 轮判 failed → 永远出不了音频。
- 根因（实测确认，三层叠加）：
  1. `_chat_completion` **从没传 `max_tokens`**，兼容端点默认 1024，长稿必被截断；
  2. glm-4-flash 返回的 JSON **写残**（`finish_reason=stop` 但尾部不闭合/单引号），
     `_parse_json_block` 解析失败就整篇丢弃，**且不留任何日志**；
  3. 即使解析成功，免费模型一次也只写 900–1500 字，够不到 1500 字下限。
- 修：
  1. `_chat_completion` 增加 `max_tokens` 参数（素材按上限 ×1.6 传）；
  2. `_parse_json_block` 三级降级：整体解析 → `_repair_json`（去尾逗号 / 补括号 / 单引号键名）
     → `_salvage_fields`（正则把 title/body/concept_keys 抢回来，不整篇丢）；
  3. 新增 `_extend_body()`：不够下限就续写补足（最多 3 轮，检测复读即停），
     审核改写 `_rewrite_body` 也接同一套续写，避免"过短 → 改写 → 还是过短"死循环；
  4. 解析失败写 `Err.log`（带 provider / 长度 / 首尾片段），不再静默。
- 文件：`backend/services/generator.py`、`backend/services/review_service.py`

### H8 · 计算器把乘号当 Markdown 删掉
- 现象：`/api/tools/calc` 对"三除以八再乘一百"返回 422 `invalid syntax`。
- 原因：`re.sub(r"[`*\n]", "", content)` 本意去 Markdown，结果把**乘号 `*` 全删了**：
  `(3/8)*100` → `(3/8)100` → 语法错误。所有含乘法的口述算式必然失败。
- 修：只剥 Markdown 外壳（反引号 / `**加粗**` / 行首列表符号），保留运算符；
  另加 prompt 硬规则（禁止 `%` 号），并对 `%` 等非法残留做一次清洗重试；
  失败时 422 的 detail 带上算式，方便排查。
- 实测：`三除以八再乘一百 → 37.5`、`3/8 百分之多少 → 37.5`、`(12+8)*5 → 100`、`二的十次方 → 1024`，4/4 通过。
- 文件：`backend/routers/english_tools.py`
