## 子 Agent 全局刁难复检发现并已修复
- 【编译级】`esp_https_ota_config_t` 根本没有 `http_handle` 成员（IDF 从未有此字段）→ 上一版 `ota_bg.c` 从没编译过。改用官方唯一注入头的方式：`.http_config = &http` + `.http_client_init_cb`（在 cb 里 `esp_http_client_set_header("Cookie","zsid=..")`；v5.1 cb 无 user_ctx，Cookie 串放 file-static）。并删除调用方对 client 的 init/cleanup——esp_https_ota 自己管理，手动 cleanup 会 double free。
- 【构建级】IDF 5.1 不认工程根 `VERSION` 文件（只认 `version.txt`/`git describe`，否则恒为 `"1"`）→ 版本永远比不上 manifest → 无限重下+重启。删除 `VERSION`，改在顶层 `CMakeLists.txt` `set(PROJECT_VER "1.0.0")`（project() 之前，IDF 明确支持 `if(NOT DEFINED PROJECT_VER)`）。
- 【逻辑级】`main.c` 用“连续运行 6h”判 OTA，但板子 15min idle 就 deep-sleep、唤醒后 `esp_timer_get_time()` 归零 → 条件永不成立，后台 OTA 事实上从不触发。改为“每次开机查一次 + 开机后 2 分钟延时 + 未在播放时”，配合每日 06:00 唤醒形成每日检查。
- 【健壮性】`esp_http_client_init()` 可能返回 NULL（坏 `server_url`/OOM），而 `net_http.c`、`download_mgr.c` 未判空就 `set_header`（直接解引用 `client->request`）→ 开机必经路径空指针崩溃。三处（含 `ota_bg.c`）补 `if(!c) return false;`。
- 【诊断/边界】`fetch_latest_version` 复用修好的 `net_http_get`（带 Cookie 且 body 累积正确），去掉旧的 perform+read 恒空 bug；相对 url 补绝对时检查 `snprintf` 返回值，拼不下直接放弃；`s_err` 用 `esp_err_to_name(e)` 而非裸数字。

## 硬件到位后仍需真机验证（本轮无法覆盖）
- OTA 下载会阻塞主循环（单次 socket 超时 60s，无总时长上限）：音频/I2S 实装后应改手动 begin/perform/finish + 总 deadline，并在临近定点关机时跳过。
- esp_https_ota 不校验 manifest `sha256`（仅校验镜像头 checksum）；服务端 latest 宜实时算 bin 摘要并拒绝不一致组合。
- 长跑设备 sid 会话过期（30 天）后接口静默 401，需重登录逻辑；每日唤醒会重登录，暂不触发。
