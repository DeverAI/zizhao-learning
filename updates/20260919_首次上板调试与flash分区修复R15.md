## 本轮做了什么

ESP32-S3-PICO-1（原生 USB-Serial-JTAG，COM13），逐步定位并修复两个上电复位循环，最终板子稳定启动到配网 SoftAP。

### 编译链环境坑（本机 Windows，记进 reference）
- `idf_tools.py` 检测到 `MSYSTEM` 报 "MSys/Mingw is not supported" → 用**原生 PowerShell** 且清 `MSYSTEM/MINGW_PREFIX/MSYS`。
- `IDF_PYTHON_ENV_PATH` 必须指 `.espressif/python_env/idf5.1_py3.11_env`（含 `Scripts/python.exe` 且有 click）；conda 的 `envs/idf` 没有 `Scripts/python.exe`，指它会 "No module named 'click'"。默认 `python`=3.14，IDF 5.1 不支持。
- `PYTHONUTF8=1`：中文 Windows 下 kconfgen 默认按 GBK 读带中文注释的 `sdkconfig.defaults` 会 UnicodeDecodeError。
- 中文路径破坏 cmake/ninja 与 PowerShell 读 .ps1 → 拷到 ASCII 路径 `C:\esp\zproj` 构建；`C:\esp\build.ps1 / flash.ps1 / monitor.ps1 / capture.ps1` 为封装脚本。
- 大下载（IDF/子模块）用断点续传+并发：`git init + fetch --depth 1 tag + submodule update --jobs 8` 外层重试循环（用户网络加速会中途断）。

### 修复 1：flash 容量 8MB（非 16MB）
症状：`spi_flash: Detected size(8192k) smaller than ... header(16384k). Probe failed.` → `assert failed: do_core_init startup.c:357 (flash_ret == ESP_OK)` 复位循环。
- `sdkconfig.defaults`：`CONFIG_ESPTOOLPY_FLASHSIZE_16MB` → `_8MB`。
- `partitions.csv`：删除 `storage`(spiffs 2M)、`fat`(6M) 两个 flash 分区，只留 nvs/otadata/phy_init/ota_0(3M)/ota_1(3M)，累加到 0x620000≈6.125MiB ≤ 8MiB。依据：`offline_store.c`/`download_mgr.c` 的 `BASE "/sdcard"`，离线音频/文本走 **Micro SD（SPI 挂载）**，不占 flash；全仓 Grep 确认无代码/构建引用被删分区名。

### 修复 2：WiFi 初始化顺序 + 缺 netif/event-loop
症状：`ESP_ERROR_CHECK failed 0x103 (ESP_ERR_INVALID_STATE) @ esp_netif_create_default_wifi_ap → esp_wifi_set_default_wifi_ap_handlers` → abort 复位循环。
- `main.c app_main`：`nvs_flash_init()` 后一次性 `esp_netif_init()` + `esp_event_loop_create_default()`（STA/AP 的 `esp_netif_create_default_wifi_*` 都依赖它们）。
- `provision_ap.c provision_ap_start()`：改为**先 `esp_wifi_init()` 再 `esp_netif_create_default_wifi_ap()`**（AP netif glue 会注册 WiFi RX handler，须驱动先 init）；`esp_wifi_init` 容忍重复调用的 `ESP_ERR_INVALID_STATE`。
- `main.c wifi_sta_start()`：同理，`esp_wifi_init()` 提到 `esp_netif_create_default_wifi_sta()` 之前。

### 顺带修掉的编译错误（本次 bring-up 期间）
- `volume_guard.h` 补 `<stdbool.h>`、`net_http.h` 补 `<stddef.h>`、`main.c` 补 `<sys/time.h>`。
- `net_http.c`：`user_ctx` → `user_data`（IDF 5.1 `esp_http_client_config_t`/`_event_t` 字段名）。
- `download_mgr.c`：`char tmp[96]` → `char tmp[sizeof(dest)+8]`，修 `"%s.new"` 的 format-truncation。

## 实机验证（idf_monitor 采集）
boot 正常：分区表 8MB / nvs+otadata+phy+ota_0/ota_1(各3M) → `cpu_start` → `app_main` → SD 无卡优雅告警 → `btn ready` → `eink: MSG 请现场配网` → `wifi:mode : softAP (70:04:1d:d7:b8:49)` → `prov: SoftAP Zizhao-Setup-B849` → `esp_netif_lwip: DHCP server started ... 192.168.4.1`。15s 内无 `Rebooting`/`Guru Meditation`/`abort`。

采集坑（记进 FreqErr）：裸 .NET `SerialPort` 采 S3 原生 USB boot 日志时，芯片复位会让 USB-JTAG 桥重枚举、句柄变 stale（只剩一行 ESP-ROM）；若"读空即重开端口"，每次 `Open()` 的 DTR/RTS 又硬复位一次，日志刷成一串相同 `ESP-ROM` → 看着像崩溃循环实为自测假象。改用 `idf_monitor`（连接即复位+自动重连）采一次开机。

## 故障检测复核（子AGENT，general-purpose，只读）
确认：分区表偏移/对齐自洽、删分区无悬挂引用、回滚不需额外分区、SD 无卡路径优雅、两处 WiFi 入口幂等、netif/event-loop 唯一、双 netif 不冲突。真机 boot 已修好。
本轮**新发现但未处理**（均属既有设计缺口/安全项，超出"让板子启动"范围，留待用户定夺）：
- P0：配网门户是 stub，无凭据时死循环常开射频不深睡；只有 device_id+passkey 无 wifi 凭据时"既不起 AP 也不联网"静默死局。
- P1：STA 路径全 `ESP_ERROR_CHECK`（一次网络异常即复位循环）；无断线重连；OTA 失败无退避会每日 ping-pong；OTA 双触发点 + 重启/深睡前不 unmount SD；SoftAP 全开放无密码 + OTA 无 sha256/证书钉（`manifest.sha256` 从未使用）。
- P2：PSRAM 未启用（BOARD 写 8MB PSRAM，字库/帧缓冲将挤爆 262KB DRAM）；多个死函数无调用；音量静音无 codec 落地；eink 全 stub 不能用屏判成败；buttons 占用 GPIO0/3 与 BOOT/JTAG strap 共用；`esp_wifi_get_mac`/`netif_create` 返回值未判。
