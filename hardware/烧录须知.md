## 人话结论（2026-09-22）：屏为什么调了一天都不亮

一句话：**屏的电不是 USB 供的，要由一颗电源芯片（AXP2101）开出来；而那颗芯片我们今天一次都没跟它说上话——
整条 I²C 总线上 112 个地址一个都没应答。所以固件里"开屏电 → 判活 → 刷白"的第一步就卡住了，后面那些代码一行都没机会跑，屏自然一直是黑的。**

已经排除的（都靠真机日志，不靠猜）：
- **不是我们固件写错**：官方自己的例程烧进同一块板也开不出电源芯片——它打的逐字是
  `E (453) axp2101: I2C read failed: addr=0x34, reg=0x03, len=1, err=-1` 紧跟 `Init PMU FAILED!`
  （`20260921_官方例程对照COM14_复位起抓20s.log:70-71`，0x34 的 0x03 就是芯片 ID 寄存器，`err=-1` = ESP_FAIL，与我们那行
  `AXP@0x34 no reply … err=ESP_FAIL` 同一种失败）。**必须交代的一半**：那两只"对照日志"是**我们自己插了心跳打印的
  `vtest_epd` 构建**，不是官方原封不动的镜像 ⇒ 它证明的是"官方那套 I²C 写法在同一块板上同样读不到 0x34"，
  不是"官方出厂固件原样跑也失败"。
- **不是 I²C 驱动/控制器的问题**：位碰探针把两套硬件状态机全绕开，只靠 GPIO 手动当时钟，结果同型（`ACK=0 NACK=112`）。
- **不是引脚表写反**：SDA/SCL 对调重跑，读数一模一样。
- **不是速度太快**：慢到 20kHz、给足上升时间，SCL 每拍都能抬到位（`9clk_high=9/9`），仍然没人应答。
- **不是驱动能力/上升沿质量（【2026-09-22 20:55 这最后一步已经走完】）**：R38 那档"主机把 SCL 主动推高"（R39 补同址复现列、R40 定"门"的编号口径：`bb_probe()` 里 `pp_skip` 那一条链是**六道**，`bb_pp_scan_all()` 体内另有**两道不编号**早退，见下面〇-补）**已烧进板子并读出判决**：
  `推挽段 ACK=0 NACK=112 首ACK=none`、`9clk_high=9/9`、`回读=cap0` ⇒ 命中六档链第⑤档，**主机侧连"边沿质量"这一维也是实测排除的**，不再是"写好待烧"。

PMIC 根本没开出任何电源轨，屏是断电的，BUSY 那个高是**它内部上拉**（与我们自己日志里 `stayed HIGH (40ms)` 同一件事）。
它的正确用法有两条：① 佐证"BUSY 读高 ≠ 屏在忙/屏活着"，这正是我们把判活做成"先高后低 + 归因给 SWRESET"的理由；
② 官方 `EPD_ReadBusy()` 是**无超时死等**，所以这份日志说明那条路径会把板子永远卡住 ⇒ 我们的 `EPD_BUSY_TIMEOUT_MS=8000`
"一次全刷要多久"**仍然没有任何量级数据**（todo 第 62 条不变）。

剩下的解释只有三个，都要**硬件条件**才能分开，光改代码分不开：
1. **电源芯片自己没上电**（PMIC 处在 ship/关机模式，需要接电池或按电源键）——这是最被看好的一条，
   但用户明确说明"不方便，只靠固件自测"，所以它现在记作**当前不可验证**，不是已排除。
2. **I²C 那 4.7K 上拉所在的一轨是 0V**（读数是 SDA 被外部钉高、SCL 只跟内部 45K 走，与"那一轨没电"不矛盾）。
3. **焊接/器件本身坏**（这块板曾经过 8:02 的出厂残留画面，说明屏和主控都曾经活着，所以更可能是"电没到"而不是"焊坏了"）。

**下一步该做的事只有一件**：接上电池、按一次电源键（约 2 秒松开，没反应再按满 4 秒；这两个时长都没有出处，
见【〇】里"门限未核实"那一段，所以要**两个都试过一次**才算排除），再把 USB 冷插一次
（深睡会把串口一起断电，不重插抓不到日志），然后跑 `C:\esp\r34_flash.ps1`。只要那几行里出现一次
`ACK>0`，"责任在固件"这个嫌疑就彻底出局，屏电也就跟着开出来了。

## 〇、先决条件：屏幕要亮，屏电必须经 I²C 让 PMIC 开出来（原因尚未定案）

本板的墨水屏电轨（AXP2101 **ALDO3**）**只能经 I²C 让 PMIC 开出来**（官方 demo 点屏第一步 `EPD_Power_ON()`；
R33 把这条引用写全：`ESP-IDF/08_ESP32-S3_e-Paper-3.97/components/epaper_port/epaper_port.c:182-186`，函数体里就一句 `enapwrstate(ALDO3)`（`:184`），
它是 `EPD_Init()` 的第一条语句 `:236`。`enapwrstate` 是随板 wrapper（`…/08_…/components/axpPower/axp_prot.cpp:197-213`，`case ALDO3: return axp2101.enableALDO3();` 在 `:206-207`），
`enableALDO3()` 的实现
`…/08_…/components/axpPower/src/XPowersAXP2101.tpp:1840-1842` = `setRegisterBit(0x90, 2)`。
**注意"只能"这句话的证据分两截**：芯片侧（哪个寄存器哪一位控制 ALDO3、官方点屏开的是哪一路）已由上面这些盘中文件证实；
"ALDO3 这一路在本板上真的喂到屏的 EPD_VCC"仍只是照官方写法采信 + 原理图口径，**没有万用表核过**。
所以：**只插 USB 时 ESP32 照常跑（串口日志、配网热点、OTA 全正常），但屏一直是黑的，
同时整条 I²C（PMIC/PCF85063/SHTC3/QMI8658）扫不到任何应答。** 改代码、重烧、"短接重置"都无效——**但"因为是没接电池"这句不是结论，是待验证的假设**（见下）。

两种解释还没定案，2026-09-20 读原理图之后第 ② 条反而更被看好：
- ① PMIC 要"开机"之后 TWI 才活 ⇒ 动作＝接电池 + 按电源键。
- ② **我方 I²C 通路本身不通**（引脚表/端口/外部上拉那一轨）。图纸口径：`VCC3V3` 就是 PMIC 的 DCDC1 输出，
  同一轨还喂着 I²C 的 4.7K 上拉；MCU 现在能跑 ⇒ PMIC 有电、上拉有电 ⇒ 0 应答更该算在通路上。
  这条图纸读数也还没在实板核对，所以两条都留着。

**这两条不需要万用表就能分开**：看每轮必打的那一行计数（见下）。

操作口径：**接上电池，按住电源键约 2 秒后松开；没反应再按满 4 秒**（两个时长都要试过一次才算排除）。
给不出唯一数字的原因：官方 demo 的 `XPOWERS_POWERON_1S`/`XPOWERS_POWEROFF_4S` 那两句
（`ESP-IDF/08_ESP32-S3_e-Paper-3.97/components/axpPower/axp_prot.cpp:76` 与 `:61`）**要 I²C 写成功才生效**，我们的固件从没写到过，
所以实板门限是芯片默认值、没核实过；手册口径又写"长按 4 秒开机"。本文在"1~2 秒"和"按满 4 秒"之间来回改过两轮，
都是在猜同一条没有出处的数——见排查记录 §十二-1 / §十三-2。
屏电晚到也没关系：固件里有后台面板监视（前 30 分钟每 5s 一轮，之后每 60s 一轮、**不会永久放弃**），电一到位自动开 ALDO3 并点屏，**不需要重烧也不需要复位**。

```
W axp: AXP@0x34 no reply (probe#1 err=... id=...) | known ...: ACK=0 NACK=4 TMO=0 ... | PWR_OUT pu=1 pd=0 → ... 悬空 ...
W epd: panel rail not confirmed (AXP unreachable or ALDO3 off): 接电池 + 按住电源键 2 秒后松开，没反应再按满 4 秒
W prov: SoftAP Zizhao-Setup-XXXX — portal http://192.168.4.1/
```
之后每 5s 重复 `axp/epd` 那一对警告行（头 3 轮和每 60 轮——偏移 30、刻意错开每 12 轮那一次判活——才多打一次全地址扫描 + 电轨对读判定），
然后**不再有更多输出**——空 NVS 时固件停在“等待配网”闸门（每 2s 读 NVS），不进主循环、不刷时钟，这是设计如此。

## 四、配网（AP 门户做完前，直接写 NVS）

固件需 5 个键（命名空间 `zizhao`）：`device_id` `passkey` `server_url` `wifi_ssid` `wifi_pass`。
- `device_id/passkey`：网页“设备”页签发。
- `server_url`：后端地址，形如 `http://192.168.1.50:8010`，**末尾不要带 `/`**；手机能打开该地址为准，防火墙放行 8010。

在**仓库外**（如 `%TEMP%`）建 `nvs.csv`（不要把含 passkey 的文件放进仓库，避免误提交）：
```csv
key,type,encoding,value
zizhao,namespace,,
device_id,data,string,dev_xxxxxxxx
passkey,data,string,网页签发的passkey
server_url,data,string,http://192.168.1.50:8010
wifi_ssid,data,string,你的WiFi名
wifi_pass,data,string,你的WiFi密码
```
生成并写入（`nvs` 分区偏移 `0x9000`、大小 `0x6000`）：
```powershell
python "$env:IDF_PATH\components\nvs_flash\nvs_partition_generator\nvs_partition_gen.py" generate "$env:TEMP\nvs.csv" "$env:TEMP\nvs.bin" 0x6000
idf.py -p COM3 flash
python -m esptool --chip esp32s3 -p COM3 -b 460800 --before default_reset --after hard_reset write_flash 0x9000 "$env:TEMP\nvs.bin"
idf.py -p COM3 monitor     # 应见 clock: SNTP synced / http time synced、zizhao: login ok
```
> 校时：SNTP（UDP123）优先，校园网常封，失败自动走 `GET /api/system/time` HTTP 兜底（该接口后端已列入免鉴权白名单）。
> 配网 SoftAP 口令（代码里的符号 `PROV_PASS`，本文件一律不抄明文）**在两台服务器上的状态相反**：ht305 那台的载荷含 `main/provision_ap.c` ⇒ 那份副本带明文（已往返逐字节坐实）；mindog 那台的载荷把它闸掉了 ⇒ 按名字证明没有。
> ⇒ 从 ht305 取回的文件要当"带明文"处理，别当干净件转发；两台的结论不得互相套用（读数：`hardware/20260924_mindog首次同步取证.txt`、排查记录 §38.2 / §38.6）。两处服务器都**只建不删** ⇒ 都不是回滚源，回滚源只有 `backups/`。
> **判"能不能 `git push`"只有一条口径**：逐提交核**未推送区间**，且**每只提交要同时看"树"与"它自己的 patch"**（树干净 ∧ patch 干净才算干净提交）。`git grep HEAD`=0 与"全树扫"都量不到这一层——本仓库 09-24 实测：区间 12 只里**树口径 6 只脏 / push 口径 7 只脏**，多的那只是**做脱敏的那次提交**（它删掉的两行就是明文）。逐只读数：`hardware/20260924_未推送历史明文普查.txt`、排查记录 **§38.7**。

## 五、易踩坑清单

1. **屏幕不亮 ≠ 驱动写坏，但也≠"肯定是没接电池"**：真因目前**没有已证实的解释**（R24 读原理图后，"PMIC 整块没电"这条已被推翻，见排查记录 §13.1）。零成本第一步仍是接电池 + 按电源键（2 秒、不行按满 4 秒），但**判案要看每轮 `known …: ACK=/NACK=/TMO=` 那一行**：有任何 ACK ⇒ 责任在器件侧；全 TIMEOUT ⇒ 大概率我方通路；全 NACK ⇒ 什么都定不了，必须配 `pull compare` 一起看（§14.3）。接了电池后 5~60s 内会自己白闪一下（后台监视），不需要重烧。
2. **`idf.py flash` 不擦整颗 Flash**，只覆盖镜像区，不会清掉已写好的 NVS；要彻底重来用 `idf.py -p COM3 erase-flash`（会连 NVS 一起擦）。
3. **独立 EN/RST 键：本仓库未登记、也没肉眼确认过有没有**（`BOARD_ePaper397.md` 只记了拨轮 + PWR + BOOT 三个交互件）。需要进下载模式时用一定有效的动作：**按住 BOOT 的同时把 USB 拔出再插回**；若实板确有复位键，按它更便宜，但**这一条从未测过**，别当既定手段（§〇-补末尾那条订正同源）。
4. **反复重启/报 flash 相关**：该板可能为 DIO 封装，`menuconfig` 把 Flash SPI mode 改 DIO、降速再 build。
5. **`sdkconfig.defaults` 只在没有 `sdkconfig` 时生效**：改过默认配置（如 ALLOW_HTTP、回滚）要先删 `sdkconfig` 再 `set-target`。
6. **别把凭据文件放进 git**：`.gitignore` 已盖 `__pycache__`/`settings.json`/`storage/`/`backups/`，但不盖 `%TEMP%` 之外的 `nvs.csv/nvs.bin`。

## 六、后台 OTA 须知（无需用户操作，但要知道规则）

- 无“升级固件”按钮；板子**每次开机后约 2 分钟**静默查一次 `GET /api/device/firmware/latest`（带 `zsid` Cookie），设备每日定时唤醒形成每日检查。
- 版本比对来源：顶层 `CMakeLists.txt` 的 `set(PROJECT_VER "x.y.z")`（**不是** `VERSION` 文件，IDF 5.1 不认）。**发版必须同步改 `PROJECT_VER` 与服务端 `manifest.json` 的 `version`**，否则要么不更新要么每轮重下。
- 发版：改 `PROJECT_VER` → `idf.py build` → 把 **`build/zizhao_esp32s3.bin`**（勿拷成 bootloader/partition_table）放为 `storage/firmware/firmware.bin` → 更新 `storage/firmware/manifest.json` 的 `version`/`sha256`。
- manifest 的 `url` 可写相对 `/api/device/firmware/bin`，固件自动补绝对地址。
- 双 OTA 分区 + 已启用回滚：烧录/断电中途不变砖。注意 `esp_ota_mark_app_valid_cancel_rollback()` 目前在**跑到稳态即调用、不校验登录是否成功**，所以它防的是“刷坏镜像起不来”，并不能保证“连不上后端的新固件会自动回退”——真机联调时若要加强，应把确认点移到登录/取包成功之后。
- 若后端 `settings` 里设了 `api_password`，全局中间件会对**未列入免鉴权白名单**的接口要求 Bearer，而固件只带 `zsid` Cookie、不发 Bearer，`/api/device/firmware/latest`、`/api/offline/bundle`、`/api/device/power` 等会全部 401。后台给板子用的部署**不要设 `api_password`**（或把这些路径加入 `_OPEN_PATHS`）。

## 七、真机联调仍需处理

- 音频播放（I2S/ES8311/MP3）、captive 门户真机 HTML 走查、RTC 跨日唤醒实测。
- ~~SD 引脚待核对~~ 已定案：SD 卡是 **SDMMC**（CLK16/CMD17/D0 15/D1 7/D2 8/D3 18，1-bit 模式），
  **不能**再用 SPI 的 39/40/41/42 —— 41/42 是 AXP2101 的 SDA/SCL，一旦被 SD SPI 占用，电源芯片就永远 0 ACK、屏永远点不亮。
- 墨水屏"真机肉眼校准"（排版留白、局刷残留灰影、深睡后面板状态）仍待电池到位后完成。驱动侧那几条无需仪器的判活日志（`PWR_OUT`/`bus scan`/`pull compare`/`known ACK-NACK-TMO`/位碰四档）**已经在真机上打过**：R33 于 2026-09-21 21:16 之后烧进 COM14，R34/R35/R36/R37 各一次，官方 08 例程也单独烧过一次做对照（文件与 md5 在排查记录 §23.2）。旧版这句"但 R23~R32 一次都没烧进板子（第十九次复查仍只剩 COM3/4/5/6）"是当时的排口状态，已作废。
  **仍然没有的那一条**：屏亮不亮**至今零次肉眼确认**——这些固件只把日志判据跑通了，全刷/局刷那条路径（`panel blanked`、主动判活 1.85s）一次都没执行过，因为它排在"屏电确认"之后，而屏电从没确认成功。
- OTA 下载目前阻塞主循环（仅单次 socket 60s 超时，无总时长上限）；音频实装后应改手动 begin/perform/finish + 总 deadline，并在临近定点关机时跳过。
- esp_https_ota 只校验镜像头，不校验 manifest `sha256`；公网部署需 HTTPS + 钉证书，并改后端 `SESSION_SECRET` 默认值。
