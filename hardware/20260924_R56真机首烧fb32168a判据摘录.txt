== 判读（只写这几臂能支撑的话）==
1）C 臂证明 R53 那一步"补官方 esp_gpio_Init 同档的 GPIO1 拉住"**确实进了镜像并且在跑**：
   boot 指纹对得上 + 开机 467 ms 有 PWR_OUT(GPIO1) hold = input+pull-up 这一行 + 770 ms 有一次 hold-on 探针。
2）同一个 C 臂把 R53 的**根因判定否证**了：hold-on 探针把 GPIO1 从"输入+上拉"升成"推挽输出高"之后，
   0x34 仍不应答、5 个已知邻居 ACK=0 NACK=5、随后整条总线 112 个地址仍 0 应答。
   ⇒ "GPIO1 没被拉住所以 PMIC 没上电所以全 NACK"这一条因果链，在**外部 5V 已接**的前提下不成立。
3）排查记录第 316 行本来就有图纸口径：电源键走 Key1 经 R26 510R 到 PWRON(30) 脚，**不接任何 GPIO**；
   第 104 行：官方 pcf85063_bsp.h 里 PWR_OUT_PIN = GPIO1 是 AXP2101 的**开机状态输出**（输入+内部上拉读它）。
   ⇒ GPIO1 是"PMIC 说它开没开"的脚，不是"固件叫 PMIC 开机"的脚。R53 把方向读反了；
   C 臂那一步等价于官方同档（输入+上拉），**无害**，但它不可能改变 PMIC 的开机状态，所以 D 臂改用物理按键。
4）D 臂是**第一个真样本**（USB + 锂电池都在位、按键确认真按过）：29 条 0x34 行仍全 no reply，
   全程 PWR_OUT 对读只有一种组合 pu=1 pd=0 = 这根脚始终悬空 = PMIC 从头到尾没有宣布自己开机。
   按排查记录 §13-2 的分流口径：**全 NACK 不定案**，所以这里只能说"按键没有把 PMIC 带进开机态（就本次这次按下而言）"，
   不能定案是"PMIC 坏"，因为还有三条没分开：电池电压/座子接触、Key1 到 PWRON 那段网络（含 510R 虚焊）、PWR_OUT 脚号登记是否对。
5）"按了但板上没有任何反应"这句是用户口述，本文件把它当**输入前提**登记（D 臂靠它才成立），不当取证读数；
   我方固件按图纸读不到按键（PWRON 不接 GPIO），所以没有任何独立手段能证明这次按下的时长与落点。
