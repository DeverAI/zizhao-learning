# R18 · 设备侧协议联调（模拟器打真实后端）+ 3 处后端修复

## 背景
用户"那联调啊等什么"。ESP32 真机的 STA 连现场 WiFi + 墨水屏刷新暂不具备条件（eink 驱动仍是桩），故先做可全自动的一层：用一个临时 Python 模拟器（OS 临时目录，非仓库代码）**严格照固件真实请求形状**打运行中的后端 `127.0.0.1:8010`，覆盖设备全生命周期契约。

## 模拟器覆盖（对齐 net_http.c / clock_sync.c / power_policy.c / ota_bg.c）
正向：邮箱码走本地 outbox 登录（smtp 未配→不发真邮件）→ `POST /device/provision` 拿 device_id+passkey →（扮演板子，无 cookie）`GET /api/system/time` 按 strstr("unix") 解析并校验区间 → `POST /api/auth/device/login` 按固件 strstr("sid") 解析 sid → 带 `Cookie: zsid=` 拉 `/api/offline/bundle`、`/api/device/power`（解析 shutdown/boot hhmm）、`POST /api/material/progress`（固件 body 形状）→ `GET /api/device/firmware/latest` 200 → 拉 bin → **下载字节==content-length 且 sha256==manifest**。
负向：错 passkey→401、无 cookie 拉 bundle/power/firmware_latest→401、撤销设备后原证书登录→401、清理固件后 firmware/latest→404。
结果：带临时固件时 **25/25 PASS**；删固件后仅剩"固件在位"两条正向断言按预期转 404。

## 联调中查出并修复的后端问题（3 处）
1. `routers/device_fw.py` `firmware_latest`：读 manifest 的 except 补 `UnicodeDecodeError`（编码坏的 manifest 原本会变裸 traceback；现与既有 JSONDecodeError/OSError 同归 "bad manifest" 500）。
2. `config.py` `load_settings`：except 补 `UnicodeDecodeError`。`load_settings()` 在**每请求中间件**（main.py:148）调用，settings.json 若被存成非 UTF-8 → 未捕获异常会让**全站 500**，半径远大于 OTA。与修法1同类，一次补上。
3. `routers/material.py` `archive_body`（`GET /api/material/archive/{id}/body`）：**无鉴权 + material_id 直拼文件路径 → Windows 反斜杠穿越**（`..%5C` 编码可越目录读任意 .txt；实测曾 200 回 requirements.txt）。修法：入口按 id 真实形态 `uuid4().hex[:12]` 严格白名单 `re.fullmatch([0-9a-fA-F]{1,64})`，不合规→400；顺带给该 open 补 `UnicodeDecodeError`。验证：`..\`/`%5C`/超长/注入味均 400，合法 hex 仍 404（不误伤真实调用方）。

## 复核（空上下文故障检测子 agent）纠正的两点认知（写清，别再夸大）
- **bundle `degraded=true` 的真因不是"无音频"**，而是该设备用户在库中**无今日素材**（`offline_service` 仅在 `not mat` 时置 degraded），那条 814B 实为空包（material=null）。
- **模拟器 ≠ 真机**：以下差异使"联调 PASS"仅代表 HTTP 契约，不代表真板子行为已通——
  - 真机 `net_http_report_progress` 的 material_id 恒 `"00000000"`（`main.c` 传的 hash 恒 0），模拟器写的随机值无消费者；`total_ms` 不带时后端 `upsert_progress` 会清零 Web 端记录（未改，属 progress 特性范围）。
  - 真机拉包走 `download_mgr.c` 落 SD，**从不调 `net_http_get_bundle`**；音频按前 4KB 嗅探 `audio_ready`，而正文常 >4KB → 有音频时真机可能恒显"仅文字"；且真机请求的 `/api/media/seg/...` 后端**无此路由**（音频整条链路未通）。
  - OTA 真机 `ota_bg.c` **只解析 version/url，不校验 sha256**（完整性仅后端自证）。
- 这些多为固件侧/音频特性，当前 `ENABLE_MATERIAL_AUDIO` 未接线 + eink 桩，不阻塞"网页可用"，但**真机联调前必须逐项走真硬件验证**，不得据本模拟器结果宣称设备可用。
