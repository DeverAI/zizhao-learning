## 二、"屏不亮"的根因定位（R20，任务 46a–46g）

1. **先修掉一个我自己埋的真 bug**：`offline_store.c` 把 SD 卡按 SPI 接在 MOSI40/**MISO41**/SCLK39/**CS42**，
   而 41/42 正是 AXP2101 的 SDA/SCL —— 挂载成功就等于永久霸占 I²C。改成官方 **1-bit SDMMC**
   （CLK16/CMD17/D0 15/D1 7/D2 8/D3 18）。
2. **开机不再被点屏拖住**：删 `EPD_INIT_RETRY_MS=30000` 阻塞窗口 → 快速失败（实测 722ms 判失败 /
   862ms 挂后台监视 / 1132ms 配网热点起来）+ 后台 `panel_watch_task` 周期重探。
3. **OTA 回滚确认**提前到 `eink_init()` 之前，消除"点屏耗时逼近 bootloader 回滚窗口"的变砖隐患。
4. **无示波器/无万用表的三条独立判据**（`axp_panel_power.c`）：
   - 全地址 0x08–0x77 扫描：**0 ACK 且返回 `ESP_FAIL`(NACK) 而非 `TIMEOUT`** ⇒ 波形在动，是没器件应答，不是驱动 bug；
   - I²C 两路对读（只开内部上拉 / 只开内部下拉）：`pullUP SDA=1 SCL=1 | pullDOWN SDA=1 SCL=0`；
   - AXP 自己的开机状态脚 **PWR_OUT=GPIO1**（官方 `pcf85063_bsp.h`）两路对读：**两块板都是 `pu=1 pd=0` = 悬空**。
   ⇒ 三条同向：**AXP2101 整块没有供电**（USB 只喂 ESP32 那一路），屏电轨 ALDO3 自然无输出。
5. **排除"变砖"**：两板都能枚举、只读 `esptool flash_id` 得到 8MB flash + 8MB PSRAM
   （COM14 `70:04:1d:d8:75:8c`、COM13 `70:04:1d:d7:b8:48`）、都能刷入并跑起配网 SoftAP，无 panic 无复位循环。
   ⇒ 用户提的"短接重置"**没有必要**，已明确告知。
6. 厂商预编译 bin 是 **16MB 合并镜像**（factory 15MB），8MB 板刷不进，做不了 factory 对照；
   官方 08 demo 需 IDF≥5.2 的新 `driver/i2c_master.h`，本机 5.1.6 编不动 ⇒ 对照改走"官方源码逐条对表 + 硬件状态脚"。

## 三、R20b：空上下文对抗审查后的修复（本轮主体）

审查报告口径 2×P0 / 5×P1 / 若干 P2，逐条落地：

- **P0-1 BUSY 电平方向判反**（`epd_driver.c`）。官方 `epaper_port.c:23-29` 写
  `.pull_up_en = GPIO_PULLDOWN_ENABLE`，而 `GPIO_PULLUP_ENABLE == GPIO_PULLDOWN_ENABLE == 1`
  且 `gpio_config()` 只判真假 ⇒ **官方实际是内部上拉**，我此前"官方用下拉"的判断被字面骗了。
  已改为显式 `GPIO_PULLUP_ENABLE`，并把判活标准从"看到一次高→低沿"改成
  **"看到持续 ≥1ms 的低电平（面板在主动驱动）"**：上拉下掉电线路只会恒高，唯一能读到低的来源就是面板本身。
- **P0-2 判活采样会漏短脉冲 + 不让出 CPU**：旧代码 `0x12` 之后先 `vTaskDelay(20ms)` 才采（软复位忙脉冲可能只有几毫秒 ⇒ 漏采），
  且随后 2s 的 200µs 紧密循环全程不释放 CPU。改成"50ms × 50µs 密采（连续 20 次去抖）→ 10ms 粗采并 `vTaskDelay`"，总窗仍约 1.85s。
- **P1 面板半路掉电拖死调用方**：`epd_display_full()` 以前忽略 `epd_panel_init()` 返回值 ⇒ 每次刷新白等 1.85s+8s，
  调用方包括 main 时钟页和 httpd 配网任务。现在 init 失败/等 BUSY 超时都清 `s_ready` 并立即返回；
  `present()` 末尾 `rewatch_if_panel_gone()` 发现 `!epd_ready()` 就撤 `s_panel_ok` 重挂监视（电回来自动复明）。
- **P1 监视任务 30 分钟后永久放弃** ⇒ 改成前 30 分钟 5s 一轮、之后 60s 一轮且**不再退出**；
  加 `s_watch_running` 幂等守卫（否则 `panel_watch_start()` 重复调用会起两个任务同时抢 SPI）。
- **P1 48KB 帧缓冲分配失败无任何恢复路径** ⇒ 抽出 `ensure_fb()`，开机失败也挂监视、每轮补分配。
- **P1 `draw_wrapped` 行缓冲真 bug**：`char line[96]` 未初始化就送 `measure_text()`，且换行只 `li=0` 不写 `line[0]=0`
  ⇒ 第二行起宽度把上一行残留全算进去（该断不断 + 小栈任务往栈外扫）。已 `= {0}` + 出行后置 `line[0]=0`。
- **P1 AXP 写完不回读**：不查 `axp_write_reg()` 返回值、无条件打 `enabled` ⇒ 现在回读 0x90/0x94 按位断言，
  位没置上就 `s_axp_off=true` 并把 `axp_enable_panel_rail()` 返回值改成 `!s_axp_off`（宁可不点屏，也不给出假"已开轨"）。
- **P2 日志与杂项**：全地址扫描（实测一次约 2.24s，不是原注释写的 1s）节流从每 20 轮改到每 60 轮；
  `app_main()` 里 `esp_log_level_set("gpio", ESP_LOG_WARN)`（GPIO 驱动每轮刷 6 行状态，会冲掉 axp/epd 诊断行）；
  `epd_sleep()` 结束释放 CS/DC 并置 `s_ready=false`；`offline_store.c` 里"释放 SPI 总线"的过时注释改为 SDMMC；
  `uxTaskGetStackHighWaterMark()` 的单位纠正为**字节**（IDF 内核 `prvTaskCheckFreeStackSpace` 按 0xa5 逐字节数），
  实测 6144B 监视任务栈剩 4008B。

# 四、R22 第二轮审查落地：忙等语义、引脚倒灌、换行截断（2026-09-20 晚）

## 一、本轮改了什么（逐条对账）

| # | 问题（第二轮审查提出） | 处置 | 位置 |
|---|------------------------|------|------|
| P1-1 | 监视任务优先级 2 高于 main(1)：一个从未验证成功的后台任务，可以在 main 渲染中途抢走 CPU 并长期持有显示锁（一次全刷最坏 8s），把配网/按键/OTA 全推后 | 优先级 2 → **1**（与 main 同级、按 tick 轮转）。锁**照旧保留**：同优先级仍会在 main 的一次刷新中途切进来翻 CS，注释同步改写为"同优先级只是轮转，整段仍须在锁里" | `eink_display.c: panel_watch_task()/panel_watch_start()` |
| P1-2 | `epd_wait_busy()` 只认"最后变高"，无法区分"面板接受了刷新"与"面板整段时间装死"：`0x20` 之后若 BUSY 从头到尾没高过（面板没吃下这条命令），旧实现会当成成功 → 屏幕什么都没变但状态机记成"已刷" | 重写为 `epd_wait_busy_ms(timeout_ms, bool require_high)`：`require_high=true` 时"先见高再见低"才算成功，`seen_high<0` 直接判失败并打 `BUSY never went high ... panel did not accept this update`；`require_high=false` 给"等空闲"用。包装 `epd_wait_busy()`/`epd_wait_idle()` | `epd_driver.c: epd_wait_busy_ms()` |
| P1-3 | `epd_panel_init()` 尾部 300ms 空闲校验只告警不失败 = "我以为它空闲了"：真卡住时后面整串写 RAM 的命令会被面板忽略，却返回 true → 假成功 | 失败改为 `return false`，日志 `panel still busy 300ms after init: skip this refresh`，由上层清 `s_ready`、监视任务下一轮重来 | `epd_driver.c: epd_panel_init()` |

## 三、这一批抓到的两条"我自己上一轮引进"的错（最重要）

1. **判读支点落在未文档化的硬件行为上**（P0-1）：`i2c_master_write(len=0)` 在这版 legacy 驱动里
   仍会生成 `byte_num=0` 的 WRITE 命令字，健康总线也可能因此读成 `ESP_ERR_TIMEOUT` ——
   会把"我方通路坏/器件侧坏"两条判读**对调**。已换成 1 字节读事务。
2. **修闸门时没回看新放行路径的不变量**（P0-2）：`eink_sleep()` 只看 `s_lock` 之后，`epd_sleep()`
   会在"引脚配过、面板从未活过"的组合下把 CS/DC 钉高，向可能 0V 的面板经 ESD 二极管倒灌整个深睡期。
   已改为归高阻。**"归到已知空闲态"≠"驱动到某个电平"**。

`FreqErr.md` 对应新增：《把"协议规范上合法"当成"这版驱动实现里等价"》《修一处闸门时只验要救的那条路径，
不回看新被放行路径破坏了哪条既有不变量》。
